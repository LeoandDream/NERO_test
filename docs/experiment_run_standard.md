# 实验、Run 与证据记录规范

状态：Step 2B 已采用；适用于**新 Run**。正式操作与安全许可仍由 [PROJECT_DESIGN.md](../PROJECT_DESIGN.md) 决定。历史原件不迁移、不改写；本规范不授予设备操作权限。状态索引见 [CURRENT_STATE.md](../CURRENT_STATE.md)，测试分级见 [test_tiers_audit.md](test_tiers_audit.md)。

## 最小记录

**Experiment** 先定义要回答的问题、适用站点/机器人/安装/工具、允许的起点条件、输入与代码来源、预设验收、停止条件。**Run** 是一次实际尝试，含拒绝、取消和故障；记录 UTC 时间及本地时区、实际参数、实际起点和终点的带时刻反馈或 UNKNOWN、代码/环境身份、执行到哪一阶段、结果、偏离计划、原件路径与 SHA-256。简单实验可在同一 Markdown 合写，不要求三份文件或固定 ID 格式。

代码身份至少有 HEAD、分支、dirty 状态。工作树影响本次执行时，附相关差异的持久引用或相关文件哈希；未跟踪的执行代码/配置同样列路径和哈希，不能仅写 HEAD。环境身份至少可定位实际解释器路径与版本、已安装 SDK 和关键依赖的版本/来源、固件/机器人、安装和工具、配置路径及哈希。未采集写 **UNKNOWN**，不据 `environment.yml` 推断本机已安装版本。计划与 Run 应引用其所用代码/配置的**执行时**身份。

每次硬件尝试写简短的人类总结：目的、实际执行和阶段、结果与主要证据、异常、适用范围、未证明事项和下一步。纯动作前拒绝可用几行。机器反馈、操作者目视或触觉观察分别标注来源、时刻和观察人/提供者；Agent 可起草，不代替现场人员确认。报告中的成功是指定命题和条件下的成功，不自动授予下一次动作许可。

证据标签作用于**具体命题**，每项注明条件、时间、代码/环境版本、原件和缺项：

| 标签 | 可说明的事实 |
| --- | --- |
| `DOCUMENTED` | 历史报告或人所述，尚未在本轮重新核实。 |
| `CODE_CONFIRMED` | 指定版本源码静态核对的调用与门禁。 |
| `OFFLINE_TESTED` | 明确的离线命令在明确版本运行并有结果。测试源码存在不算。 |
| `HARDWARE_EXECUTED` | 设备命令尝试、发送或反馈发生；须说清到哪一步。 |
| `HARDWARE_VERIFIED` | 指定验收的前后反馈及所需现场观察齐备。只对该条件和命题成立。 |

缺证据写 `UNKNOWN`。这些标签不是总分，也不同于能力的 Experimental → Verified → Promoted；一个 Run 通过不自动晋升正式 Runtime。

## 原件、引用与收尾

原始 CSV、CAN 记录、同期生成的运行/失败 JSON 及已有哈希链**不原地覆盖**。错误通过新勘误、分析或完成凭证表达，附源文件、SHA-256、替代关系和结论适用范围；派生图标明源哈希与方法版本。当前状态索引可替换旧摘要，历史报告的重要结论和原因须先持久化。可变配置 JSON 不因本规则一概变成原件，但执行时使用的版本/哈希必须可定位。历史旧路径、schema 和锁定状态保留；旧记录被新实验使用时重新审核其资格。

新引用优先写 `repo:<相对项目根路径>`，并列该文件 SHA-256 与解析基准（仓库根、HEAD/工作树快照）。外部文件写完整定位方式和哈希；旧绝对路径用新增映射说明，不改旧字节。**目前未证明**旧回放入口在迁移目录后兼容。已核实的保管位置仅是项目工作区与现有 Git 跟踪范围；物理备份、责任人和保留期限尚无核实依据，本规范不作承诺。

每次执行把关键变更、命令/参数、检查结果、失败或放弃原因、证据位置、未完成项和续接条件写入对应正式报告、Run Summary 或现有追加记录。无代码改动的审计也记录范围与结论。`CURRENT_STATE.md` 只在实质状态改变时更新；不默认每个 Session 建文件。交付顺序为 Goal、Changed、Verified、Not Verified、New Risks、Remaining、Next。
