# Design Change Proposal：非 H0 低位启动到 S1

状态：用户已批准受限恢复方案；当前仅有实验代码与离线检查，**尚无本路线的实机验收**。编写于 2026-09-27，基于 `main@caf3c2b` 与当时未提交的工作树。适用目标仅为左侧安装、裸法兰的单臂实验。

## 冲突事实与原因

- 用户执行 `python -m experiments.single_arm.lab.cli quick init --target S1`，被通用回位入口以法兰 X=0.038 m < 0.150 m 拒绝。该 0.150 m 门槛自 `planned_return.py` 首次提交 `060d349` 起就存在，Git 回退不能解决此例。
- 用户提供的 2026-09-27 12:09:42 UTC 只读反馈为 `CAN_CTRL`、`NORMAL`、七轴使能、零错误，关节角 `[0.257715, 0.017558, 0.071279, -0.157097, 0.003787, 0.131929, 0.060860]` rad，法兰 XYZ `[0.038189, -0.010809, 0.718404]` m。用户称当时法兰未接触桌边，安装与线缆布局一致。该反馈只证明采样时设备状态，不能证明路线安全或之后的状态。
- 与已验收的 H0 关节角最大单轴差约 1.656 rad，超过命名 H0 的 0.01 rad 识别门槛；与 S1 最大单轴差约 0.596 rad。当前低 X 时的 Y=-0.010809 m，比 H0 专用路线在 X<0.10 m 时要求的 Y≤-0.034 m 靠桌侧约 23.2 mm。因此不能把当前点冒充 H0，也不能直接复用 H0 的首段离桌动作。
- 既有通用规划器只抽查法兰中心的 FK 与关节盒；没有完整桌边、支撑和线缆模型。直接把 X 门槛降至 0.038 m 或更低，会让未验证的路线通过入口，不能证明不会碰桌边。

## 最简单替代

保留通用规划器的 X≥0.150 m 门槛和 H0 精确识别。为当前站点增加一个**显式低位恢复候选**：先从新鲜七轴反馈规划到已允许的通用规划区域，再由现有 `quick init --target S1` 规划后段。正式自动选择需要版本化的安装/工具/桌边/支撑/线缆事实、起点姿态范围和实机验证记录同时匹配；这些证据尚不齐备，因此当前只允许窄姿态识别后的现场受监护单目标试验，不授予通用自动恢复许可。其它低位继续拒绝，不得调用锁定的旧 H0 路线。

首个离线候选限定在用户贴出的起点七轴角各轴 ±0.01 rad 内：J3 到 −0.30 rad、J1 到 0 rad、J2 到 −0.30 rad，再用通用规划器到 S1。模型预估低位前三段法兰 X 最小约 0.024 m，Y 先从约 −0.011 到 −0.035 m，之后 J2 才将 X 提到约 0.204 m。它是**供首次现场审阅的候选**，不是实体桌边、连杆和线缆的碰撞证明。运行时重读状态和配置、核对起点与现场、限定速度并逐目标验收；任何状态变化、接触或路径无法证明时停止后续目标，保留实测停点，不自动复位、失能或继续到 S1。既有 `execute_route` 对已发送运动后的异常可能请求阻尼电子急停，其下垂风险继续适用。

实现责任应落在现有实验 `lab` 规划与分流文件内；正式 Runtime 的 Environment + Safety/Workflows 契约只在批准后同步更新。先更新 `PROJECT_DESIGN.md` 与 `PROJECT_MAP.md`，再修改代码。不增加平行的 `v2` 入口。

## 影响与验证条件

- 操作契约从“未知低位拒绝”扩展为“有站点专用许可和证据的有限低位恢复”，属于安全标准和路线治理变更。旧 H0/S1 已验收路径、锁定入口及历史原件不得改变。
- 离线：用纯内存假状态测试命名 H0、当前非 H0 低位、环境不匹配、起点漂移、失败中途停止；对候选路线审计裸臂及桌边模型。按 `docs/test_tiers_audit.md` 审核导入链后，只运行明确 T0/T1 的目标测试。
- 实机：在站点条件和具体路线另行确认后，先只读生成并审阅各目标和扫过范围；首次单目标低速试验记录逐时状态、实际轨迹、现场桌边/线缆间隙，再分段验收至 S1。达到 S1 且状态正常才可标记成功。当前方案 **NOT_RUN**，无实机许可。

用户已批准上述有限例外。待决事项：桌边和支撑几何、当前姿态至通用区域的首段真实路径尚无实体模型；首次实机仍须现场审阅路线、确认全部扫过范围，并在异常时停止。当前代码采用严格起点识别、低速单目标暂停和现场确认来约束首次试验；它不等于对全连杆或控制器实际路径完成碰撞证明，也无法保证 `quick init` 从这组姿态成功。

## 2026-09-27 连续完成方式的用户修订

首个 J3 目标已获现场正常反馈。用户随后明确选择“**一次命令跑完整路线**”，而非单个 `move_j` 直达。这授权在同一窄姿态、同一站点、全程有人监护和完整扫过范围现场确认的条件下，增加显式 `--complete-low-route` 选项：仍按原计划的多个 `move_j` 目标、2% 速度和逐目标反馈运行，最终独立验收到 S1；其它异常沿原执行器停止后续目标并报告实测停点。不改变默认逐目标暂停、通用 X 门槛、H0 路线或锁定入口。该选项不支持 `--yes`，执行前重读并重新规划；无现场全范围确认不得使用。单个 `move_j` 直达经只读抽查被拒绝，因为异步关节盒包含全零禁区姿态；它不在本次修订范围。

13:01–13:02 UTC，用户使用显式选项运行了阶段 1 起点到 S1 的剩余 5 个目标；执行报告显示 5/5 到位，独立只读状态在 S1、NORMAL、七轴使能。该结果证明本次控制器目标与最终姿态，**不能在缺少现场观察时断言整片路线无桌边、支撑或线缆接触**；完整实体验收仍待用户回复。
