# CAN 连通与状态实验报告

## 目的与条件

验证 Nero 单臂通过 `can0` 独立与 Python SDK 通信，区分 CAN 链路、机械臂使能和拖动模式。设备使用 1 Mbps SocketCAN，环境为 `nero-py310`，固件档位为 `NeroFW.V121`；详细命令见[使用说明](README.md)。

## 过程与结果

2026-09-23 已通过 CAN 查询固件 1.21，接收关节和法兰反馈；没有启动网页上位机。初期红灯时控制器报告 `JOINT_BRAKE_NOT_RELEASED`，七个驱动未使能。后续通过 CAN 使能后出现绿灯，进入左侧装拖动示教时由现场人员扶稳机械臂。红灯阶段的[诊断 CSV](data/nero_poses_20260923T133556Z_red_light_diagnostic.csv)只用于故障排查。

2026-09-24 重启后重新启用 `can0` 并恢复通信。链路是否 UP、控制器是否正常、驱动是否使能是三个不同检查项；CAN 接口 UP 本身不代表机械臂已使能。机械臂后续完成 S1 移动、轨迹回放和法兰 X 方向往返，说明当次 CAN 通路可用于受监护控制。

同日的 20 秒示教回放在返程触发电子急停后，使用[专用恢复脚本](recover_emergency_stop.py)只读检查，并在现场机械支撑就位后显式发送一次 `reset()`。[恢复记录](data/recoveries/nero_emergency_recovery_20260924T111407Z.json)显示第一次复位后反馈为 `NORMAL`、错误码零，关节角与复位前相同。详细事件和后续只读核对见[电子急停与实验恢复](../../../docs/emergency_stop_recovery.md)。

## 结论与边界

本机固件可经 CAN 直接通信；当前安装方向按左侧装使用。使能或切入拖动模式可能引起运动，实机操作仍需现场确认底座、零点和活动范围。历史诊断记录不能作为自动运动目标。

2026-09-24 再次由本机命令行查询得到固件 `1.21`、SDK 档位 `v121`。随后只读状态检查显示 `CAN_CTRL`、`NORMAL`、示教禁用、错误码 `0x0000`，七个驱动均使能，电压约 `23.5～23.9 V`。
